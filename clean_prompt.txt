   🖼️ AREA 3: Image Optimization (Biggest Win) 



   

     ⚠️ 

      Root problem:  All your images are served from  qubetatechnolab.com  — an external server. This means an extra DNS lookup, no Vercel CDN optimization, no WebP conversion, and no lazy loading control. Move images to your own  /public  folder or use Vercel Image Optimization. 

   



   

     

       HIGH 

       next.config.js — Enable Image Optimization 

       Code 

     

       // next.config.js 

 /** @type {import('next').NextConfig} */ 

 const  nextConfig = {

  images: {

    formats: [ 'image/avif' ,  'image/webp' ],  // serve AVIF → WebP → JPEG fallback 

    remotePatterns: [

      {

        protocol:  'https' ,

        hostname:  'qubetatechnolab.com' ,   // allow current CDN temporarily 

        pathname:  '/public/PetSaathi/**' ,

      },

    ],

    deviceSizes: [ 360 ,  414 ,  768 ,  1024 ,  1280 ],  // India device breakpoints 

    minimumCacheTTL:  86400 ,   // cache images 24h 

  },

  compress:  true ,

  poweredByHeader:  false ,

  async headers() {

     return  [

      {

        source:  '/:path*.{jpg,jpeg,png,gif,webp,avif,svg,ico}' ,

        headers: [

          { key:  'Cache-Control' , value:  'public, max-age=31536000, immutable'  }

        ],

      },

      {

        source:  '/_next/static/:path*' ,

        headers: [

          { key:  'Cache-Control' , value:  'public, max-age=31536000, immutable'  }

        ],

      },

    ];

  },

};



 module.exports  = nextConfig;

   ❓ Q&A Deep Dives 



   

     🤔 Why is mobile score lower than desktop? 

     

       Mobile PageSpeed is harder because: (1) CPU throttled to 4x slower than desktop, (2) bandwidth simulated at ~1.6 Mbps 3G, (3) viewport is narrow so images/fonts must be mobile-optimized. India's user base is predominantly mobile (85%+ on Android), so fixing mobile score is your highest priority. 

       The biggest mobile killers for PetSaathi are: large unoptimized images, external image CDN (qubetatechnolab.com), and render-blocking resources. 

     

   



   

     🤔 What is LCP and how do I fix it specifically? 

     

        LCP = Largest Contentful Paint  — the time until the biggest visible element is rendered. For PetSaathi it's almost certainly the hero image or hero headline. 

        Target: under 2.5s on mobile.  

       Fix it in 3 steps: 

       

         Put the hero image in your own  /public  folder (not qubetatechnolab.com) 

         Add  priority  prop to the Next.js <Image> (this generates a <link rel="preload">) 

         Convert the hero to WebP and serve at the right size (max 800px wide for mobile) 

       

     

   



   

     🤔 What is CLS and why does it hurt my score? 

     

        CLS = Cumulative Layout Shift  — measures how much content jumps around as the page loads. Users hate it. Google penalizes it. 

       On PetSaathi, CLS is caused by images loading without explicit dimensions — the browser doesn't know how tall the image will be, so it reserves no space, then shifts everything down when the image appears. 

        Fix:  Add  width  and  height  attributes to every single image. One-line fix, huge score improvement. 

        < img   src = "dog.webp"   width = "400"   height = "300"   alt = "..." >  

     

   



   

     🤔 How do I check my actual PageSpeed score after fixing? 

     

       Run:  pagespeed.web.dev  — paste your URL and select Mobile tab. 

       Also run locally using Lighthouse in Chrome DevTools → Lighthouse tab → Mobile → Analyze. This gives you line-by-line breakdowns without waiting for the public report. 

       After each batch of fixes, re-run the report and compare. Target:  Performance > 70  on mobile. 

     

   



   

     🤔 Should I move off qubetatechnolab.com for hosting images? 

     

        Yes, as soon as possible.  When images come from a third-party domain, users' browsers must: 

       

         Look up qubetatechnolab.com's DNS (extra ~50–200ms on mobile) 

         Establish a new HTTPS connection (another ~100ms) 

         Download the image (unoptimized, probably JPG/PNG not WebP) 

       

       When you host on Vercel, Next.js's Image Optimization automatically converts to WebP/AVIF, resizes for device, caches on CDN, and serves from the same domain — saving 300–500ms per image on mobile. 

     

   



   

     🤔 How do I target Indian users specifically in PageSpeed? 

     

       PageSpeed uses US-based servers. Your real Indian users may have different results. To get India-specific data: 

       

         Use  WebPageTest.org  → set location to "Bangalore" or "Mumbai", connection to "4G India" 

         Enable  Vercel Speed Insights  — shows real user CWV data segmented by country/device 

         Use  GTmetrix  → select Mumbai server location 

       

       Also: optimize for low-end Android phones (the dominant India device). Simulate in Chrome DevTools → CPU throttle 6x, Network throttle "Fast 3G".
